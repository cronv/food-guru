# Публикация на сервере reg.ru

Короткий путь: облачный сервер reg.ru, архив проекта со своей машины и один скрипт.
Подробности про устройство проекта, ручную установку и решение проблем — в [DEPLOY.md](DEPLOY.md).

## 1. Сервер

В личном кабинете reg.ru закажите облачный сервер (VPS):

- **Образ:** Ubuntu 24.04 или Alpine Linux, если он есть в списке образов. Скрипт
  работает с обоими, а также с Debian.
- **Память:** от 2 ГБ, лучше 4 ГБ. При 2 ГБ скрипт сам добавит своп для сборки
  Angular, но сборка пойдёт медленнее.
- **Диск:** от 20 ГБ. Образы Docker занимают около 5 ГБ, остальное — база и загрузки.

Запишите IP-адрес и пароль root из письма или карточки сервера.

## 2. DNS

Домен `food-guru.ru` должен работать на DNS-серверах reg.ru (`ns1.reg.ru`, `ns2.reg.ru`).
В карточке домена откройте управление DNS-зоной и добавьте четыре A-записи на IP сервера:

| Поддомен | Тип | Значение |
| --- | --- | --- |
| `@` | A | IP сервера |
| `www` | A | IP сервера |
| `api` | A | IP сервера |
| `admin` | A | IP сервера |

Записи обновляются от нескольких минут до суток. Проверить можно со своей машины:
`nslookup api.food-guru.ru` должен вернуть IP сервера. Пока записи не обновились,
HTTPS не заработает: Let's Encrypt выдаёт сертификат только домену, который уже
указывает на сервер.

Если домен другой — замените `food-guru.ru` во всех файлах из списка в начале
[DEPLOY.md](DEPLOY.md) **до** сборки архива.

## 3. Почта

Без SMTP не уходят письма подтверждения и входа, то есть зарегистрироваться на сайте
нельзя. Подойдёт почта для домена от reg.ru или любой почтовый сервис. Параметры
SMTP — сервер, порт, логин — смотрите в настройках почтового ящика в кабинете.
Используйте порт **465** или **587**: порт 25 на VPS обычно закрыт.

Их вы впишете в `backend/.env` на шаге 5.

## 4. Архив и загрузка

На своей машине, в папке проекта:

```powershell
powershell -ExecutionPolicy Bypass -File tools\make-release.ps1
```

Получится `release\food-guru-ГГГГММДД-ЧЧММ.tar.gz` — код без `node_modules`, сборок
и файлов `.env`. Загрузите его на сервер:

```powershell
scp release\food-guru-*.tar.gz root@IP-СЕРВЕРА:/root/
```

## 5. Установка

```sh
ssh root@IP-СЕРВЕРА

mkdir -p /srv/food-guru
tar -xzf /root/food-guru-*.tar.gz -C /srv/food-guru
cd /srv/food-guru

# Первый запуск: Docker, пароли, сборка (10–15 минут), HTTPS,
# демо-данные и ваш аккаунт администратора.
sh deploy.sh --seed --admin вы@почта.ru "Имя Фамилия"
```

Скрипт предупредит, что почта не настроена. Впишите SMTP и запустите его ещё раз —
пароли и ключи при этом не меняются:

```sh
vi backend/.env      # MAIL_HOST, MAIL_PORT, MAIL_USERNAME, MAIL_PASSWORD, MAIL_FROM_ADDRESS
sh deploy.sh
```

В конце скрипт проверит сайт, API и админку по HTTPS и покажет коды ответа: везде
должно быть `200`.

## 6. Проверка

- [ ] `https://food-guru.ru` открывается, замок в браузере без предупреждений
- [ ] `http://food-guru.ru` и `https://www.food-guru.ru` переводят на `https://food-guru.ru`
- [ ] `admin.food-guru.ru` → «По ссылке» → письмо пришло → пароль задан, вход работает
- [ ] Ссылка на рецепт, отправленная себе в Telegram, показывает превью с картинкой
- [ ] Остальное — по чек-листу в [DEPLOY.md](DEPLOY.md)

## Обновление

На своей машине соберите новый архив и загрузите его, как в шаге 4. На сервере:

```sh
cd /srv/food-guru
tar -xzf /root/food-guru-НОВЫЙ.tar.gz -C /srv/food-guru
sh deploy.sh
```

Файлы `.env` в архиве нет, поэтому настройки и пароли сохраняются. Удалённые из
проекта файлы на сервере останутся — на работу сайта это не влияет.

## Резервные копии

Всё ценное лежит в томах Docker: база (`mysql-data`) и загрузки (`storage-app`,
`storage-public`). Плюс два файла `.env` — без `APP_KEY` из `backend/.env` не
расшифруются сессии и зашифрованные поля. Простой ежедневный бэкап базы:

```sh
cd /srv/food-guru
docker compose -f docker-compose.prod.yml exec -T mysql \
  sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction food_guru' \
  | gzip > /root/backup-$(date +%F).sql.gz
```

Копии храните не на том же сервере: в кабинете reg.ru можно включить снимки
сервера целиком.

## Если что-то не так

```sh
cd /srv/food-guru
alias dc='docker compose -f docker-compose.prod.yml -f docker-compose.https.yml'
dc ps
dc logs caddy --tail=50    # сертификаты: ошибки Let's Encrypt, DNS
dc logs php ssr nginx --tail=50
```

**HTTPS не поднимается, в логе caddy ошибки `challenge`.** Домен ещё не указывает
на сервер или указывает не туда — проверьте A-записи (шаг 2). Caddy повторяет попытки
сам, перезапускать ничего не нужно.

**Скрипт пишет «домен указывает на …, а у этого сервера …», хотя IP верный.**
Значит, публичный адрес не висит на сетевом интерфейсе (сервер за NAT). Если
`nslookup` показывает IP сервера — всё в порядке, это только предупреждение.
