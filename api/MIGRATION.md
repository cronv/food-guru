# Переезд бэкенда с Laravel на Symfony

Новый бэкенд — Symfony 7.4 LTS (исправления ошибок до ноября 2028, безопасности до
ноября 2029), PHP 8.5. Переезжаем поэтапно, по модулям: старый бэкенд (`backend/`)
и новый (`api/`) работают одновременно на одной базе и под одним адресом API.

## Правила переезда

1. **Контракт API не меняется.** Адреса, коды ответов, формат JSON и ошибок — как
   у Laravel. Angular-фронтенды не трогаем. Каждый перенесённый адрес проверяется
   сравнением ответов обоих бэкендов (`tools/contract`).
2. **Одна база, один владелец схемы.** До последнего этапа схему меняют только
   миграции Laravel. Symfony отображает существующие таблицы сущностями Doctrine
   и миграций не создаёт. На последнем этапе схема переходит к Doctrine Migrations
   (базовая миграция с текущего состояния).
3. **Переключение — строкой в nginx.** Список перенесённых адресов лежит в
   `docker/nginx/symfony-routes.conf`. Откат модуля — удалить его строку.
4. **Вход Symfony.** Сессии ведёт Symfony (cookie `FGSESSID`, файлы в `var/sessions`).
   XSRF-TOKEN подписан секретом приложения (`src/Security/Xsrf.php`). Мост к сессиям
   Laravel удалён на этапе 5: пользователям после переключения нужно войти заново один раз.
5. **Модуль считается перенесённым**, когда: тесты Symfony повторяют тесты Laravel
   для этого модуля, контрактное сравнение чистое, PHPStan и php-cs-fixer чистые,
   адрес включён в nginx и неделю работает без ошибок в логах. После этого код
   модуля в Laravel удаляется — отдельным шагом с согласования.

## Слои совместимости

На время переезда в `src/Api` живут части, которые
повторяют Laravel дословно. После выключения Laravel их можно заменить на
обычные средства Symfony — когда фронтенд перестанет зависеть от этих форматов.

- `InputValidator` — правила и английские тексты валидации Laravel, свои русские
  тексты контроллеров, ответ 422 `{message, errors}`. Замена — Symfony Validator.
- `LaravelPaginator` — формат `paginate()`: `data`, `links`, `meta` с окном ссылок.

Чтение каталога написано на DBAL (`src/Catalog`): SQL повторяет форму запросов
Eloquent, чтобы при равных значениях сортировки порядок строк совпадал с Laravel.

## Соответствие частей

| Laravel | Symfony |
| --- | --- |
| Eloquent-модели | Сущности Doctrine (`src/Entity`) на тех же таблицах |
| Контроллеры + `routes/api.php` | Контроллеры с атрибутами `#[Route]`, префикс `/api/v1` |
| API Resources | Нормализация в массивы (`src/Api/*Presenter`) |
| FormRequest / `validate()` | DTO + Validator, ответ 422 в формате Laravel |
| Sanctum (cookie-сессия) | Сессии Symfony (`FGSESSID`), XSRF-TOKEN через `XsrfSubscriber` |
| Политики | Voters |
| `throttle` | RateLimiter |
| Очереди, `Mail` | Messenger, Mailer |
| Планировщик | Scheduler |
| `php artisan …` | `bin/console …` |

## Найдено и исправлено по ходу

- Академия: пункты «чему научимся» делились `preg_split('/\R/')` без флага `u`.
  В байтовом режиме `\R` ловит 0x85 — второй байт кириллической «х» (D1 85), —
  и ответ падал с «Malformed UTF-8». Исправлено в обоих бэкендах, тест в Laravel
  (`AcademyAccessTest`) и в Symfony (`ContentAccessTest`).
- Мост CSRF: Laravel (Sanctum) проверяет токен на любой записи с фронтенда, даже
  у гостя. Сначала мост пропускал гостя — приведено к поведению Laravel.

- Счётчики: `$model->increment()` в Eloquent обновляет и `updated_at`. Просмотры,
  скачивания, записи на эфир, голоса, баллы — в Symfony тоже трогают дату
  изменения (от неё зависит `lastmod` в карте сайта).
- Адреса рецептов и тегов строятся той же библиотекой транслитерации, что у
  Laravel (`voku/portable-ascii`, `App\Support\Slug`): у AsciiSlugger Symfony
  «ужин» — uzhin, у Laravel — uzin, и теги задвоились бы. Эталоны — `SlugTest`.

- Тестовая оплата: в Laravel она запрещена при `APP_ENV=production`, а у Symfony
  боевое окружение зовётся `prod`. Проверка «не prod» пропустила бы тестовую оплату
  при `APP_ENV=production` из чек-листа Laravel — любой зачислял бы себе деньги.
  Поэтому в Symfony — список разрешённых: только `dev` и `test` (`TestGateway::forbidden`).
  **На боевом сервере у Symfony `APP_ENV=prod`.**
- Валидация: Laravel не останавливается на первой ошибке поля (кроме `bail` и
  проваленного `required`), пустой массив для `required` — «нет значения», размер
  строки при числовом правиле — её длина. `InputValidator` повторяет всё это.

## Известные расхождения на время переезда

- Лимит маршрута (`throttle:30,60` → `#[RouteThrottle]`): в Laravel счётчик у всех
  таких маршрутов общий на человека (ключ — только id), в Symfony — у каждого
  маршрута свой. Поведение Symfony — то, что и подразумевалось.

- Ссылки на видео закрытой академии подписывает Symfony (`UriSigner`), формат
  подписи другой. Ссылки, выданные Laravel до переключения, живут 2 часа и после
  переключения не откроются — человек обновит страницу и получит новую.
- Запасное ASCII-имя PDF журнала транслитерируется компонентом String Symfony,
  а не Str::ascii Laravel: буквы могут отличаться (основное имя в filename* то же).

- Лимит запросов считается каждым бэкендом отдельно: пока модули поделены, клиент
  может сделать до 60 запросов в минуту в каждый. После переезда лимит снова один.

## Команды

```bash
docker compose exec -u www-data api composer test    # PHPUnit (база — tests/README.md)
docker compose exec -u www-data api composer stan    # PHPStan, уровень 8
docker compose exec api composer cs                  # php-cs-fixer, @Symfony + @PER-CS
# Сравнение с Laravel (tools/contract) удалено вместе с backend/ на этапе 7.
```

Порядок переноса адреса: тесты Symfony → строка в `docker/nginx/symfony-routes.conf` →
`nginx -s reload`. Адрес уже обслуживает Symfony, поэтому строка нужна только для проверки.

`bin/console` и PHPUnit запускайте от `www-data` (`-u www-data`): так работает
php-fpm, и кэш в `var/`, созданный от root, ломал бы веб-запросы. Если всё же
запускали от root: `docker compose exec api chown -R www-data:www-data var`.
