# Food Guru — кулинарный портал

Рецепты с пересчётом граммовок, видеорецепты, отзывы читателей с фотографиями
и админ-панель с модерацией и ролями.

**Публикация на хостинге — [DEPLOY.md](DEPLOY.md).**

## Состав

| Папка | Что это |
| --- | --- |
| `backend/` | REST API на Laravel 13: 14 таблиц, роли, вход по ссылке из письма |
| `frontend/projects/site/` | Публичный сайт, Angular 18 с SSR |
| `frontend/projects/admin/` | Админ-панель, Angular 18 SPA |
| `frontend/projects/shared/` | Общие типы, API-клиент, авторизация, дизайн-токены |
| `site/` | Статический прототип витрины (работает без API) |
| `tools/reels/` | Генератор вертикальных видеорецептов |
| `docker/`, `docker-compose*.yml` | Окружение для разработки и боевого сервера |

## Запуск для разработки

```bash
# backend
cp backend/.env.example backend/.env
docker compose up -d --build
docker compose exec php composer install
docker compose exec php chown -R www-data:www-data storage bootstrap/cache
# artisan — от www-data, как работает php-fpm: иначе закрытые файлы (PDF журнала,
# видео академии) создаются от root с правами 700, и сайт отвечает на них 404.
docker compose exec -u www-data php php artisan key:generate
docker compose exec -u www-data php php artisan migrate --seed
docker compose exec -u www-data php php artisan storage:link

# frontend
cd frontend
npm install
npm start           # сайт на 4200
npm run start:admin # админка на 4300
```

| Что | Где |
| --- | --- |
| Публичный сайт | http://localhost:4200 |
| Админка | http://localhost:4300 |
| API | http://localhost:8000/api/v1 |
| Почтовый ящик (Mailhog) | http://localhost:8025 |

Письма наружу не уходят — всё оседает в Mailhog.

## Как войти

Два способа: по почте и паролю или по одноразовой ссылке из письма. Пароль
человек придумывает сразу после первого перехода по ссылке (регистрация
подтверждает почту), позже его можно задать или сменить в личном кабинете.

У демо-аккаунтов пароля нет, поэтому первый вход — по ссылке:

1. Откройте http://localhost:4300 (админка) или сайт, вкладка «По ссылке».
2. Введите почту из таблицы ниже, нажмите «Получить ссылку».
3. Откройте http://localhost:8025, найдите письмо, перейдите по ссылке.
4. На открывшейся странице задайте пароль — дальше можно входить по нему.

| Роль | Email |
| --- | --- |
| Администратор | admin@food-guru.local |
| Руководитель редакции | lead@food-guru.local |
| Контент-менеджер | manager@food-guru.local |
| Пользователь | user@food-guru.local |
| Пользователь без подтверждения | pending@food-guru.local |

На боевом сервере эти аккаунты безопасны: пароля нет, а письмо со ссылкой на
`@food-guru.local` никуда не дойдёт. Свой аккаунт администратора создайте командой
`php artisan food-guru:admin вы@почта.ru` и войдите по ссылке из письма.

## Что заложено в безопасность

- В базе лежит только SHA-256 от токена: утечка дампа не даёт войти ни в один аккаунт.
- Пароль хранится bcrypt-хешем и в ответы API не попадает. Вход по паролю — 5 попыток
  в минуту на связку «адрес + IP»; на неверный пароль и чужой адрес ответ одинаковый,
  и хеш сверяется в обоих случаях, чтобы ответы не различались по времени.
- Смена пароля требует текущий. Первый пароль — нет: письмо уже подтвердило личность.
- XSRF-cookie Sanctum кладёт в заголовок свой перехватчик (`xsrf.interceptor.ts`):
  встроенный в Angular делает это только для относительных адресов, а API на другом
  домене. Без него любой изменяющий запрос получает 419.
- Ссылка подтверждения живёт 24 часа, ссылка входа — 15 минут, обе одноразовые.
- Выпуск нового токена гасит все предыдущие того же типа.
- Токен не тратится при SSR: иначе предзагрузка мессенджера «сжигала» бы ссылку
  до того, как человек по ней перейдёт.
- Ответ на регистрацию одинаков для нового и занятого адреса — форма не работает
  как способ проверить, зарегистрирован ли человек.
- Смена почты не трогает основной адрес, пока новый не подтверждён.
- Руководитель редакции не может менять роль администратору и не может повысить себя.
- Письма со ссылками: 5 в час на связку «адрес + IP» и 30 в час с одного IP, плюс
  минутный интервал между письмами. Повторная отправка всегда отвечает 202 —
  по ответу не узнать, есть ли такой адрес и не включён ли интервал.
- Ссылка гасится одним атомарным UPDATE до входа: два одновременных перехода
  по одной ссылке не дают двух сессий (второй получает 410).
- Смена пароля закрывает все остальные сессии и меняет remember-токен; на почту
  уходит уведомление. Смена почты при заданном пароле требует текущий пароль,
  уведомление уходит на старый адрес.
- Отключённый аккаунт выкидывается из уже открытых сессий: middleware
  `EnsureAccountIsActive` на каждом запросе к API, а при отключении из админки
  сессии пользователя удаляются сразу.
- Тестовая оплата (`PAYMENT_PROVIDER=test`) в `APP_ENV=production` не запускается:
  приложение отказывается собрать платёжный шлюз, кнопка «оплатить тестом» отвечает 404.
- Контент-менеджер не публикует и не снимает товары и книги и не меняет цены
  у опубликованных — это делает руководитель редакции.
- Смена статуса заказа идёт под блокировкой строки: два менеджера не проведут
  заказ двумя разными путями, отмена возвращает деньги и остаток ровно один раз.
- Денежная история защищена в самой базе: кошельки, проводки, платежи, заказы,
  покупки и подписки ссылаются на пользователя и книгу с `RESTRICT`, каскадом
  их не стереть.
- SSR строит адрес страницы из `SITE_URL`, а не из заголовка `Host`, и движку
  разрешён только этот хост (`allowedHosts`); адреса вида `//evil.com` и с обратной
  косой уводятся на главную.
- Лимит API — 60 запросов в минуту на пользователя или IP. SSR-сервер ходит в API
  за всех посетителей с одного адреса, поэтому подписывает запросы общим секретом
  `SSR_API_KEY` и передаёт IP посетителя: лимит считается по посетителю (300 в минуту,
  одна страница — несколько запросов). Без верного ключа заголовку с IP не верим.
- Если API при рендере недоступен, страница отдаётся с кодом 503, а не 404:
  поисковик зайдёт позже, а не выкинет страницу из индекса.
- Переходы статусов рецепта проверяются по таблице допустимых переходов,
  а не просто записью нового значения.
- Расширение загруженного файла берётся из его содержимого, а не из имени.
  Правило `mimes` определяет тип по содержимому и на имя не смотрит, поэтому
  настоящий PNG с именем `photo.php` проходит проверку. Если взять расширение
  из имени, файл ложится в публичную папку как `.php`, и nginx отдаёт его
  PHP-FPM — дописанный к картинке код выполнится на сервере.
- В nginx папка загрузок объявлена через `location ^~ /storage/`. Приставка
  обязательна: без неё регулярное `location ~ \.php$` выигрывает у префиксного.
  Внутри стоит вторая страховка — `return 403` на `.php`.
- Частота запросов ограничена на всём API (`throttleApi` в `bootstrap/app.php`).
  В Laravel 13 это не включается само: лимитер объявлен в провайдере, но без
  явной строки к маршрутам не применяется.
- Заголовки безопасности повторены внутри каждого `location` со своим
  `add_header`: в nginx свой `add_header` отменяет унаследованные от `server`.
- Политика содержимого включена в режиме отчёта. Включать сразу на запрет
  нельзя не проверив живой сайт: Angular добавляет стили компонентов инлайном.

### Что остаётся на вашей стороне

- Обложку выпуска рисует `pdftoppm` из загруженного PDF. Разбор чужого PDF —
  это поверхность атаки, у poppler бывают уязвимости. Снижено тем, что PDF
  загружает только редакция, вызов идёт массивом аргументов без оболочки
  и ограничен 30 секундами. Обновляйте образ.
- Политику содержимого нужно довести до режима запрета после проверки.
- Angular 21 — LTS-ветка с исправлениями безопасности до мая 2027. `npm audit`
  чистый. Переход на 22 потребует Node.js 22.22+ на машине сборки.
- Токены и ключи в `.env` — заведите свои, примеры в репозитории не секреты.

## Фотографии

Иллюстрации нарисованы кодом: снимки из интернета не использовались, права на
графику ваши. Для демо-рецептов их делает `node tools/dishes/make_dishes.mjs` —
по три кадра на рецепт (готовое блюдо, ингредиенты, в процессе) в
`backend/database/seeders/assets/dishes/`; сидер кладёт их в медиатеку как обложку
и галерею. Тексты рецептов сидер берёт из прототипа: `node tools/dishes/export_recipes.mjs`.
В рабочем сайте фотографии загружаются через админку и читателями в отзывах.

## Видеорецепты

`tools/reels/` генерирует вертикальные ролики 1080×1920 по 20 секунд с граммовками
и подсказками. Рендер идёт в Docker, около минуты на ролик; как добавить рецепт —
в `tools/reels/README.md`. Готовые ролики для сидов лежат в
`backend/database/seeders/assets/reels/` (`<slug>.mp4`), сидер привязывает их к рецептам.

На сайте ролик стоит на странице рецепта, лентой на главной и отдельной страницей
`/reels`. Редакция загружает ролик в редакторе рецепта (MP4 или WebM до 80 МБ).

## Рецептосохранялка

Личная кулинарная книга, страница `/cookbook`. Две части: рецепты сайта, сохранённые
кнопкой «В рецептосохранялку» (таблица `cookbook_recipes`), и свои заметки — рецепт
с другого сайта по ссылке или записанный от руки (`cookbook_notes`). С избранным
(`favorites`, «нравится») это разные списки; рейтинг на главной и счётчик «сохранили»
считаются только по рецептосохранялке. В ссылке принимаются только
`http(s)`: `javascript:` превратил бы заметку в ловушку.

## Рецепты читателей

Кабинет → «Мои рецепты» → редактор (`/account/recipes/new`). Путь: черновик →
«Отправить на модерацию» → руководитель редакции публикует или возвращает с
комментарием (вкладка «На модерации» в админке открывается по умолчанию).
Автору приходит письмо о решении; за публикацию — 25 баллов рейтинга.

- На модерацию уходит только полный рецепт: фото, описание от 20 символов, время,
  от двух ингредиентов и шагов. Проверяет сервер, редактор подсказывает чек-листом.
- Читатель правит только черновики и возвращённые; на модерации — сначала
  «Забрать с проверки»; опубликованное — только редакция.
- Фото — только свои (id чужих снимков из медиатеки отклоняются), картинки до 8 МБ.
- Адрес, SEO-описание и «секреты шефа» читатель не задаёт.
- Неотправленные черновики читателей редакции не видны.

API: `/me/recipes` (список, создание), `/me/recipes/{id}` (чтение, правка, удаление),
`/me/recipes/{id}/submit`, `/me/recipes/{id}/withdraw`, `/me/recipes/media` (фото).

## Кошелёк, книги, магазин, закрытая академия

Все суммы в базе и API — целые копейки (990 ₽ = `99000`). Всё платное покупается
только с баланса кошелька: это предоплата за товары и услуги сайта, вывести деньги
нельзя, возврат — через поддержку (корректировка баланса администратором).

| Раздел | Адрес | Как устроено |
| --- | --- | --- |
| Кошелёк | `/wallet` | баланс, история, пополнение: карта, СБП, SberPay, ЮMoney, от 100 до 50 000 ₽ |
| Книги | `/books` | бесплатные и платные; ознакомительная глава открыта всем; читалка `/books/{slug}/read/{n}`; PDF с почтой покупателя на каждой странице — только бесплатным и купленным |
| Магазин | `/shop`, `/cart`, `/orders` | корзина в браузере; цены и остатки сервер проверяет сам, под блокировкой строк; доставка: самовывоз, курьер 390 ₽, почта 290 ₽ |
| Закрытая академия | `/club` | подписка на 1, 3 или 12 месяцев; продление встаёт встык; видео по подписанной ссылке на 2 часа и только пока подписка действует; подписчик читает книги «в подписке» |

**Платёжная система.** Сейчас включена тестовая (`PAYMENT_PROVIDER=test`): страница
`/wallet/pay/{id}` с кнопками «Оплатить» и «Отменить», деньги не списываются.
Настоящую подключают реализацией `App\Services\Commerce\PaymentGateway` (создать
платёж, вернуть ссылку на форму) и вебхуком, который после проверки подписи вызывает
`PaymentService::succeed()`. Повторное уведомление не зачислит деньги дважды:
у проводки уникальный `payment_id`.

**Заказы** создаются уже оплаченными. Цепочка: оплачен → собирается → отправлен →
доставлен. Покупатель отменяет сам, пока заказ не начали собирать; после — только
руководитель редакции в админке. Отмена возвращает деньги на баланс и товар на склад.

**Права в админке:** товары, книги и материалы академии — контент-менеджер и выше;
заказы — руководитель редакции; корректировка баланса — только администратор.

Демо: у `user@food-guru.local` на балансе 3 000 ₽. Видео мастер-классов в сидах —
наши рилсы, скопированные на закрытый диск; замените настоящими в админке.

## Карточка рецепта

- Справа — блок кнопок «Похожие рецепты», «Комментарии», «Пожаловаться», «В избранное»,
  «В рецептосохранялку», «Поделиться» и под ним видеорецепт. Под фото — только оценка

  кнопки прокручивают к ним; жалоба открывается в диалоге.
- Под фото — оценка (одна на человека, только с подтверждённой почтой), просмотры

- Под каждым шагом вкладки «Совет», «Замена ингредиентов», «Секреты шеф-повара» —

- Жалобы разбирает руководитель редакции в разделе «Жалобы» админки.

## Конкурсы

Конкурс заводит редакция: инфоповод, условия, приз и четыре даты — начало и конец
приёма работ, начало и конец голосования, дата итогов.

**Фаза конкурса нигде не хранится.** Она считается из дат в `Contest::phase()`.
Отдельное поле «фаза» неизбежно разошлось бы с датами: приём работ закрыт, а в базе
всё ещё «идёт приём». Из этого следует, что фазу нельзя отфильтровать в SQL —
списки отбираются по датам, подписи расставляет ресурс.

Участник присылает работу, она попадает на модерацию и только после неё — в галерею.
Голос один на конкурс, за свою работу голосовать нельзя. Единственная настоящая защита
от двойного голоса — уникальный индекс `(contest_id, user_id)`: проверка запросом
не спасает от двух одновременных запросов, поэтому код ловит нарушение индекса
и отвечает 409.

Отклонение работы с голосами обнуляет её голоса и уменьшает счётчик конкурса —
иначе сумма голосов конкурса осталась бы завышенной.

Что присылают, задаёт тип конкурса (`App\Enums\ContestKind`): фото и рецепт — до пяти
картинок по 8 МБ, видео — один файл до 100 МБ. Пределы заданы в одном месте, в енаме.

## Кулинарная академия

Три формата: вебинар, прямой эфир и видеоурок. У видеоурока нет времени старта —
он доступен сразу после публикации.

**Смотреть можно только по записи.** Расписание и описание открыты всем,
а `stream_url` и `record_url` просто отсутствуют в ответе, если человек не записан:
поля нет, а не пустая строка. Редакции обе ссылки видны всегда — иначе редактор
открыл бы форму занятия с пустыми полями и затёр бы их при сохранении.

Ссылка на эфир отдаётся только пока эфир идёт: до начала она бесполезна, а утечь успеет.

Список записавшихся — персональные данные, он доступен с уровня руководителя редакции.

## Рейтинг пользователя

Баллы начисляются за четыре вещи, цена каждой задана в `App\Enums\RatingSource`:

| Повод | Баллы |
| --- | --- |
| Заход на сайт, раз в сутки | 1 |
| Неделя заходов без пропусков | 5 |
| Опубликованный рецепт | 25 |
| Отзыв к рецепту | 5 |
| Фотоотчёт о приготовлении (сверх отзыва) | 10 |

Уровни: Новичок (0), Повар (100), Шеф (400), Гуру (1200) — `App\Enums\RatingLevel`.

**Начисление идемпотентно.** Каждое событие пишется в `rating_events` с ключом
`dedup_key`, на котором стоит уникальный индекс; вставка идёт через `insertOrIgnore`.
Проверять «а не начисляли ли уже» запросом нельзя — два одновременных запроса пройдут
проверку оба.

Ключ за отзыв привязан к паре «человек + рецепт», а не к id отзыва: иначе отзыв можно
было бы удалить и написать заново ради новых баллов.

Заход отмечает middleware `track.visit` на всех авторизованных маршрутах. Он обязан
быть дешёвым, поэтому сначала сравнивает дату в уже загруженной модели и только раз
в сутки идёт в базу. Отметка ставится в `terminate()`, после ответа: баллы не должны
задерживать отдачу страницы.

Если счётчик и журнал разойдутся, `RatingService::recalculate()` пересчитает баллы
из журнала.

### Чего пока нет

Баллы за рецепт начисляются автору при публикации (`author_id`). Сейчас рецепты
заводит редакция, поэтому своего рецепта у обычного пользователя быть не может —
публичной формы «прислать рецепт» в проекте нет. Начисление написано и заработает
в тот день, когда такая форма появится; до этого источник «опубликованный рецепт»
даёт баллы только сотрудникам редакции.

## Журнал

Выпуски — PDF с гайдами недели и месяца. Раздел фильтруется по годам и месяцам.

**PDF лежит на закрытом диске** `local` — это `storage/app/private/journal`
(в сборках Laravel до 11.21 — `storage/app/journal`), — и отдаётся только
маршрутом `/journal/{slug}/download`. Файл на `public` был бы доступен по прямой
ссылке: счётчик скачиваний перестал бы что-либо значить, а ссылка продолжала бы
работать после снятия выпуска с публикации. Поэтому путь к файлу хранится в самой
таблице выпусков, а не в медиатеке — в медиатеке лежат только картинки, и её
ресурс строит публичный URL для каждой записи.

**Год и месяц продублированы колонками** `issue_year` и `issue_month` рядом с
`issue_date`. Фильтр раздела идёт именно по ним: `YEAR(issue_date)` в условии
отключает индекс и превращает фильтр в полный перебор.

Дата выпуска приводится к началу периода: для недели — к понедельнику, для месяца —
к первому числу. Редактор может выбрать любой день внутри периода, нормализует
`JournalIssue::syncPeriodColumns()`.

Список годов и месяцев отдаёт отдельный маршрут `/journal/periods`, а не метаданные
списка. Иначе фильтр пересобирался бы под уже выбранный фильтр, и выбранный месяц
остался бы в нём единственным.

### Обложка

Редактор может загрузить картинку сам. Если не загрузил, первую страницу PDF рисует
`pdftoppm` из poppler-utils — он есть в обоих образах PHP. Число страниц читает
`pdfinfo` оттуда же.

Инструмента может не оказаться (своя сборка, другой хостинг) — тогда выпуск просто
останется без обложки и без числа страниц. Загрузку файла это не ломает: отсутствие
обложки — рабочее состояние, а не авария. В админке есть кнопка перерисовать обложку.

Опубликовать выпуск без PDF нельзя: скачивать будет нечего.

## Мобильная версия

Ниже 960px сайт ведёт себя как приложение, а не как сжатая десктопная страница.

Разделы живут в нижней панели: большой палец дотягивается до низа экрана,
а не до шапки. Ярлыков ровно пять — дальше подписи перестают читаться;
остальное открывается листом по кнопке «Ещё». Бургер в шапке при этом
убирается: два одинаковых меню на одном экране только путают.

Панель прибита к низу и учитывает безопасную зону (`env(safe-area-inset-bottom)`),
иначе на айфонах последний ярлык уезжает под системную полосу. Отступ
содержимого под панель задан в `styles.css` — без него подвал оказывается
под ней и становится недоступен.

Сайт устанавливается на домашний экран: `manifest.webmanifest`, иконки 192,
512 и отдельная maskable с безопасной зоной 80%. В установленном виде
браузерная обвязка пропадает и остаётся только приложение.

## Тесты

```bash
# бэкенд
cd backend && composer test

# фронтенд
cd frontend && npm test          # публичный сайт
cd frontend && npm run test:admin
```

Проверки кода — перед каждой выкладкой, все должны проходить без ошибок:

```bash
# бэкенд: стиль (Pint, пресет Laravel) и статический анализ (Larastan, уровень 5)
docker compose exec -u www-data php vendor/bin/pint --test
docker compose exec -u www-data php vendor/bin/phpstan analyse --memory-limit=1G

# после изменения моделей и миграций — обновить docblock'и моделей для анализатора
docker compose exec -u www-data php php artisan ide-helper:models --write --reset

# фронтенд: angular-eslint (шаблоны, доступность, префиксы селекторов)
cd frontend && npm run lint
```

`npm run build` не запускайте при работающих `npm start` / `start:admin`: они держат
кэш сборки, и боевая сборка админки молча зависает. Остановите dev-серверы, соберите,
запустите снова.

Бэкенд гоняется на SQLite в памяти — без поднятого сервера базы. Ради этого
полнотекстовые индексы в миграциях создаются только на MySQL, а поиск на
остальных драйверах уходит в LIKE (`App\Support\Searchable`). На боевой
базе поведение прежнее.
